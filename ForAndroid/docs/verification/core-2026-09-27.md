## 已验证切片

- 共享 model-io：Windows 和 Android NDK 编译同一 PLY/SPZ 探测、解码及规范化源码。Android fd 入口支持可 seek 文件与有上限、可取消的非 seek 流缓存；以共享内存返回只读场景，接收端用 `ASharedMemory_getSize` 和完整布局/内容复核后建立 `SceneHandle`。Service 进程通过 Binder 传 FD 与版本化进度，客户端过滤旧请求、识别死亡与超时。PLY 按约 4 MiB 解码块检查取消；SPZ 规范化循环检查取消，Niantic 库整包解压期间尚不支持中断。
- render-core：实际创建 Vulkan 1.1 instance/device，检查设备堆、buffer 范围与预算；`ANativeWindow` 上创建 Surface/swapchain 并 Present 三角形，`PixelCopy` 检查彩色三角形及白色背景。GLSL Vulkan 1.1 稳定 radix 排序不依赖 subgroup 宽度，读回结果与 CPU `stable_sort` 比较，夹具覆盖 0/1 点、同键、128 线程组边界、257、4097 和 65537 点随机键。每 pass 最多 3 个 storage buffer，128 线程组。
- 独立 GoogleTest：model-io 7/7、render-core 2/2；联合 GoogleTest 1/1，覆盖 PLY 解码、共享 FD 接收、GPU 准入和该场景的 GPU 稳定排序。Android 仪器测试 5/5，覆盖隔离进程与 FD 交付、空闲流取消、超时恢复、Service 被杀后重绑和 Surface 像素。100 次共享场景创建/接收/销毁后 FD 数无增长。
- 真实语料 `hornedlizard.spz`：786233 点、SH3，在模拟器上两次解码分别约 3.7 和 4.3 秒、测试进程峰值 RSS 约 409 MiB（418480–418840 KiB）。这是诊断观测，不是性能门槛。`racoonfamily.spz` 带 SPZ `antialiased` 标志，按规格返回 `UnsupportedFeature`。

固定样本 SHA-256：`hornedlizard.spz` 为 `A076CA6AEB9F1A8FE52526F4A7C381FE8FFFEC60C0D7EB64B45532189B64BC6A`；`racoonfamily.spz` 为 `2E068D893730955C09AEE324FF170C559F71C0E8758C1B14C3811A5969333CFE`。GoogleTest XML 保存在本地 `out/android-x86_64/test-results/`（构建输出，未纳入仓库）。

## 可复现命令

从仓库根目录运行，先安装已固定的 Android SDK/NDK 并设置 `ANDROID_HOME`：

```powershell
& .\ForAndroid\gradlew.bat -p ForAndroid :sdk:assembleDebug :sdk:assembleRelease
cmake -S ForAndroid -B out/android-x86_64 -G Ninja -DCMAKE_TOOLCHAIN_FILE="$env:ANDROID_HOME/ndk/27.2.12479018/build/cmake/android.toolchain.cmake" -DANDROID_ABI=x86_64 -DANDROID_PLATFORM=android-29 -DCMAKE_BUILD_TYPE=Debug
cmake --build out/android-x86_64 -j 6
& .\ForAndroid\tests\run-device-tests.ps1
& .\ForAndroid\gradlew.bat -p ForAndroid :sdk:connectedDebugAndroidTest
```

## 尚未通过的退出门槛

- `model-io`：真实 SAF provider 的 seek/non-seek/撤权测试、恶意偏移与输入长度变化注入、解码 Service 进程内存压力矩阵、SPZ 解压期间有界取消和大场景三轮峰值数据。当前 CPU 预算以实时 `MemAvailable`、布局及估算的解码峰值预检，实际失败仍回滚；这不是完整的 ActivityManager/process-limit 预算证明。
- `render-core`：场景属性/SH 分段 GPU 上传、生产帧深度键、Gaussian 投影/SH0–3/透明合成、固定相机图像、GPU timestamp、动态 GPU 分配回滚、Surface resize/旋转/丢失及 device-loss 恢复、验证层无错和资源长测。当前排序自检是同步诊断原型，尚未接入生产帧，也未证明大场景帧率。
- 任务依赖：共享相机数学、公开 C ABI、Kotlin 查看器、完整 AAR/NDK SDK 消费示例、真机 30 FPS 和跨 GPU 兼容性均未完成。当前 AAR 是内部测试宿主，不应作为正式 SDK 发布。
