# Android performance investigation, 2026-09-28

## Environment and sample

MuMu Android 15 emulator at `127.0.0.1:5561`, x86_64, landscape 1920 x 1080. Vulkan reports Adreno 640 through the emulator; this is not an Adreno phone measurement. Sample `../1.ply`, 66,061,086 bytes, 1,179,648 splats. The viewer keeps all points, SH, output pixels and stable sorting. All measurements below are diagnostic single runs, with no temperature control or three-run median.

## Loading

Initial Debug APK before loading changes: second open took 3,108 ms from selection to Ready. The stage log recorded decoder 1,033 ms, redundant client validation 610 ms, engine import 197 ms, upload 354 ms and first Present 361 ms. Another Debug run took 2,303 ms, demonstrating run-to-run variation.

The client now forwards the untrusted shared FD directly to the native import boundary. `import_shared_fd` still makes a private read-only copy, validates the full scene and checks the live memory limit before GPU upload. Large positional copies use 1 MiB chunks with cancellation checks. A separate `benchmark` build uses optimized native code (`RelWithDebInfo`) on the emulator; Debug remains available for debugging.

The final benchmark APK opened the same PLY in 1,100 ms: decoder 132 ms, import 40 ms, upload 306 ms, first Present 347 ms. A previous benchmark run measured 1,300 ms. This is an APK/profile comparison, not proof that any single edit accounts for the full difference. The 300 MB case mentioned by the user has not been measured because no matching local PLY sample was available.

## Browsing

Before changing the render schedule, the Debug APK repeatedly rendered the stationary 1.18 million splat scene at about 276-282 ms CPU frame time. The queue-idle wait accounted for about 278 ms. GPU timestamp queries did not return samples on this emulator, so projection, sort and draw GPU times are unknown.

The engine now renders on initial load, camera revision, scene replacement and Surface recreation, then sleeps while the scene is stationary. The UI's Choreographer callback likewise runs only during active free-mode movement. SDK device tests verified that idle frame count stays fixed and that orbit and Fit wake rendering. Idle application CPU was observed at 0.0% in one `top` sample.

Across 120 interaction frames generated by repeated drag gestures, the final benchmark APK averaged 327 ms per rendered frame, with 326 ms average queue wait. The logged 198-second wall interval includes idle time between gestures and is not a continuous FPS sample. Two stable radix-scatter alternatives were measured and removed: 128-lane rank counting averaged about 499 ms; 16-bin parallel scatter averaged about 306 ms against an approximately 280 ms earlier Debug baseline. Emulator variance and different builds make those comparisons directional only. Neither justified changing the stable sorter. No 30 FPS or 33.3 ms frame-time claim is made. Hardware GPU profiling and an algorithmic sort/draw improvement remain required for the A4 gate.

## Verification

`GUI:assembleDebug`, `GUI:assembleBenchmark`, `GUI:lintDebug`, GUI device tests 4/4, SDK device tests 8/8, and native device tests 32/32 passed on the emulator. Native tests include stable GPU radix sorting, timestamp counter wrap, and camera revision behavior. OCR reviewed 20 selected changed files and reported six findings; the identified wakeup, zero-size Surface spin, idle UI callback, timestamp wrap, cancellation callback and recovery action were addressed. True arm64 phone performance, equal-quality desktop comparison, sustained thermal behavior and a 300 MB PLY remain unverified.
