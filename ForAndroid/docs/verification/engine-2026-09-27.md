仪器测试在模拟器真实 `ANativeWindow` 上验证白色背景、前红后蓝的 Gaussian
透明顺序，并从 PLY 经隔离 Service、共享 FD、C ABI、Kotlin 状态流直到首帧 Ready
完成联合测试。固定/自由相机与 Y 轴镜像命令通过原生 API。发布包由
`packaging/build-sdk.ps1` 生成，仅含 `arm64-v8a` Release AAR/原生库，包含
C 头、CMake 导入配置、预编译 SPIR-V、七模块规格、操作指南、示例、许可证和
SHA-256 清单。测试用 Debug Activity 不在 Release AAR 中。

复测时 Windows CTest 的大样本联合项曾在第三个外部模型上触发助手进程的
`Helper memory limit`。按运行时可用物理内存与提交内存的 80% 调整 Job 限额及场景
准入后，单独复跑该项 1/1 及完整 Windows CTest 5/5 均通过。Vulkan 预算探针
现按实际使用的 host-coherent 缓冲内存类型选堆，避免设备本地堆与上传堆不一致时误准入。

## 尚未通过的门槛

- 无 arm64 真机，未完成代表性 Adreno/Mali 的截图、Vulkan validation、SH 1–3
  固定图像对照、30 FPS/1% low、热节流与 30 分钟长测。
- 场景 GPU 缓冲仍要求单个属性缓冲位于 `maxStorageBufferRange` 内；尚未做分段
  上传和跨段绘制。上传使用 host-coherent buffer，尚未实现设备本地内存 staging。
- 帧流水为单命令缓冲加单 fence，CPU 每帧等待完成；已有低频快照中的帧耗时，
  但 GPU 投影/排序/绘制时间戳、内存分配细分和热状态尚未实现。
- Surface 重建和设备丢失有界重建逻辑已接线，尚缺 100 次重绑、强制设备丢失、
  低内存分配失败与验证层故障注入。C ABI 的旧头/新库兼容消费和事件队列未验收。
- Kotlin 包外消费只验证编译；arm64 独立应用安装、打开模型、取消、恢复及销毁
  的运行验收需要目标真机。当前包为技术预览，不满足 `T18`–`T21` 正式发布门槛。

原型模型解码和排序的更早证据见[核心验证记录](core-2026-09-27.md)。
