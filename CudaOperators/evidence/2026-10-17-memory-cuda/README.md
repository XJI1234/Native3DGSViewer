# 共享映射计费与物理用量诊断

工具：tools/telemetry.py，逐约0.5秒调用驱动随附nvidia-smi查询全局memory.used/温度/SM时钟/功耗，同时采样基准进程与解码子进程RAM。命令、样本和返回码见telemetry.json，另一半对照见相邻memory-d3d12。此工具会产生测量干扰，仅用于资源诊断，不能与无监控正式性能混同。

22480361点、原SH3、1920×1080、2s预热/4s采样：D3D12全局显存峰值8313MiB，CUDA投影+排序8510MiB，均正常退出。运行二进制来自project-diagnostic的冻结快照，其SHA见该组results.json；模型hash同组。包含用户其他GPU程序的占用，不能把全局峰值称作该进程独占显存。

DXGI局部进程计费从约6.14GiB升至12.45GiB，而独立物理用量峰值仅增加197MiB，说明共享映射视图的计费与真实物理增量不一致。日志原样保留。生产准入必须兼顾实际私有分配、共享映射去重和全局资源压力；当前仅有原生80%准入前检查，不能将大模型的映射后预算门槛勾选通过。
