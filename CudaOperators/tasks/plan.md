依赖图：工具链 → 共享buffer → fence/帧槽 → 排序与投影 → 组合/可见集 → tile列表 → CUDA合成 → HLSL算法对照/提前终止 → 调度/Graph → 正式采集 → 胜出项集成 → 稳定性验收。

## 阶段及检查点

1. W01–W03：从NVIDIA官方13.3.0清单安装当前用户开发组件，核对SHA；支持的MSVC+C++20/SM86编译与运行；LUID/共享buffer/纹理、10000次fence往返及noop计时。
2. W04–W07：32位稳定CUB全数组排序；CUDA投影与现有D3D12数学/布局对照；各自消融与组合；稳定压缩及动态规模限制的实测。
3. W08–W11：受检tile列表、global rank等序合成、CUDA与HLSL同算法对照、提前终止阈值与误差分别验证。
4. W12–W14：先调度再Graph；按墙钟相机路径的正式30s预热/60s采样/3轮起步；各阶段与完整GPU span、呈现、显存/内存和图像证据。
5. W15–W16：仅集成超过收益与质量门槛的策略；先修改提供者契约，再接SDK/GUI；CUDA OFF、测距/恢复/部署与2小时长稳。

每阶段检查：正确性、可归因性能、所有attempt、预算、退出错误、版本和输入hash齐全；无证据不勾选。工具分析与正式计时分开。若无法运行，明确工具/硬件/资源阻塞及受影响路径，不将阻塞写成性能失败。

## 实现决定

- Toolkit安装根：当前用户AppData/Local/Native3DGSViewer/toolchains/cuda/13.3.0；下载缓存不进Git，官方清单与安装收据进evidence。
- 根CMake开关默认OFF；CUDA目标独立输出，基线二进制/hash保留。
- 后端私有DLL按需加载；公开SDK不暴露CUDA类型。早期bench先验证私有边界，不改变默认renderer。
- 以现有40字节Ellipse和160字节FrameConstants锁定布局，CUB稳定顺序与当前径向键一致。
- 精确tile先过图像门槛；提前终止、调度、Graph各自单独归因。

## 风险与处置

| 风险 | 处置 |
|---|---|
| nvcc/宿主不支持 | 官方支持区间核查与真实编译；不绕过版本检查 |
| WDDM同步固定成本抵消收益 | noop和完整span同时记录，尽量扩大连续CUDA区域 |
| tile引用数放大 | 64位计数、预算准入、明确资源失败 |
| blend舍入与排序造成图像差异 | 合成夹具/真实热图，保持稳定global rank，不放宽门槛 |
| 设备失败等待死锁 | 有界fence状态、在途资源隔离、错误注入 |
| 测量受限或噪声 | AB/BA与重复轮次；正式呈现受限标不可判定 |
